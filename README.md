# 병원 정산 3-Way 대사 시스템 (Streamlit)

한솔페이 / 일일마감 / 차트마감 데이터를 비교하여 결제수단별 차이를 분석합니다.

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 기간 대사 모드 (한솔↔차트 · 여러 날)

월(기간) 단위로 내려받은 **한솔 거래내역 + 차트마감(수납)** 파일 2개만으로, 일자별
(한솔 `거래일` ↔ 차트 **`수납일`** — 진료일 아님) 카드·현금영수증 합계를 자동 대사해
**차이가 있는 날만** 짚어줍니다. 차이가 있는 날은 승인번호(결제메모)·금액 매칭으로
설명되지 않는 거래만 추려 보여주므로(보통 0~3건) 원인 확인이 빠릅니다. 일일마감은
필요 없습니다. 첫 화면의 `분석 모드 → 기간 대사`에서 사용.

하루 정밀 대사 모드에 여러 날짜가 담긴 차트마감/한솔 파일을 올리면, 구글시트에서
고른 날짜(또는 일일마감과 차트번호 겹침이 가장 큰 수납일) 하루로 자동 필터링됩니다.

## 일일마감 구글시트 연동 (선택)

일일마감은 파일 업로드 대신 **지점별 구글 스프레드시트**에서 바로 읽어올 수 있습니다.
일일마감 입력란에서 `구글시트 연동`을 선택 → **지점 드롭다운** + **달력**으로 날짜를 고르면,
해당 날짜 이름의 워크시트(탭)를 읽어 분석합니다(파일 업로드 불필요).

설정 방법:

1. 각 지점의 일일마감 스프레드시트를 `[공유] → "링크가 있는 모든 사용자" → 뷰어`로 변경
   (별도 인증키/서비스계정 불필요).
2. `app.py` 상단의 `CLINIC_DAILY_SHEETS` 에 `{지점명: 스프레드시트 URL}` 입력.
   URL을 깃에 남기기 싫으면 `.streamlit/secrets.toml` 의 `[clinic_daily_sheets]` 섹션에 적으면
   그 값이 우선 적용됩니다.
   - 지점이 시트를 **새 파일로 이전**한 경우(예: 엔디어트 — `26.06.12`부터 새 시트), URL 대신
     `[(적용 시작일 "YYYY-MM-DD", URL), ...]` 목록을 적으면 분석 날짜에 맞는 시트가 자동
     선택됩니다(시작일 당일 포함, 빈 시작일 = 그 이전 전체의 기존 시트). 단일일·기간 분석
     모두 적용되며, 기간이 이전 시점을 걸치면 날짜별로 두 시트를 나눠 읽습니다.
3. 각 스프레드시트의 **탭 이름은 날짜**여야 합니다. 지점·시기마다 형식이 달라도
   (`26.06.02` / `06.02` / `6.2` / `26.6.2` / `2026.06.02` 등) 자동으로 맞춰 읽습니다
   (`_candidate_tab_names` 참고). 다른 형식이 필요하면 그 함수에 후보를 추가하면 됩니다.

구현 메모:

- **결제수단 머리글 보존을 위해 `export?format=csv&gid=`(셀 원본 그대로)를 1순위로 사용**합니다.
  구글 `gviz` CSV는 '숫자 열'의 텍스트 머리글(카드/현금/이체 등)을 타입 추론 과정에서
  **빈칸으로 떨어뜨려**(일산·강남 등 결제수단 머리글이 통째로 사라져 금액이 0원으로 읽힘)
  버립니다. export는 탭을 **gid(숫자)**로만 지정할 수 있어, `edit` 페이지에서 `{탭이름: gid}`
  매핑을 1회 읽어(세션 캐싱) 날짜 후보와 정확히 일치하는 탭을 고릅니다(`_sheet_gid_map`).
- **2순위 폴백은 기존 `gviz` CSV**입니다(gid 매핑을 못 얻거나 — 구글 내부 포맷 변경 등 —
  후보가 매핑에 없을 때). gviz는 탭을 못 찾으면 오류 대신 **첫 시트로 조용히 폴백**하므로,
  존재할 수 없는 이름(sentinel)의 응답과 비교해 **폴백이면 "해당 날짜 탭 없음"으로 처리**합니다
  (잘못된 시트를 진짜 데이터로 오인하는 사고 방지).
- **차트번호 열 머리글 자동복구**: 지점 시트들이 `순서|구분|차트번호|성명` 구조인데 차트번호
  열의 **머리글 칸만 비어 있어도**, 앱이 `구분` 바로 오른쪽의 무라벨 숫자열(3~7자리)을
  `차트번호`로 자동 인식합니다(`_looks_like_chart_no`). decoy 열 `이름/차트번호 중복여부`는
  머리글이 있어 영향받지 않습니다.
- 그래도 차트번호를 전혀 못 찾으면(진짜 비표준) **양식이 표준과 다르다는 경고**가 표시됩니다.

> 시트가 비공개(특정 계정만 공유)면 이 방식으로는 읽을 수 없으며, 접근 권한·시트 이름 안내
> 메시지가 표시됩니다. (예: 새 지점 추가 시 공유를 "링크가 있는 모든 사용자 - 뷰어"로 먼저 변경.)

### 교차검증 — 타 지점/다른 날짜 파일 방어

차트마감(베가스)을 업로드하면, 선택한 **일일마감과 같은 지점·같은 날짜인지** `차트번호`
겹침으로 검증합니다(`cross_check_daily_patient`). 결과는 세 가지:

- **block** — 양쪽 모두 차트번호가 있는데 일치율이 기준(`CROSS_CHECK_MIN_RATE`, 기본
  **0.6=60%**) 미만 → **합계·통계를 일절 표시하지 않고** "다른 지점/날짜 파일" 안내만 노출
  (다른 지점 데이터 엿보기 방지).
- **warn** — 한쪽에 차트번호가 없어 대조 자체가 불가(예: 비표준 일일마감) → **경고만 하고
  분석은 진행**(표준화 전환기 편의). 표준 양식으로 입력하면 자동으로 block 검증이 적용됩니다.
- **ok** — 일치율 기준 이상 → 조용히 통과.

일치율 = `|두 파일 차트번호 교집합| / min(일마 차트수, 차트 차트수)`. 같은 지점·같은 날짜면
보통 0.9 이상, 다른 지점/날짜면 0에 가깝습니다. 기준값은 `app.py` 상단
`CROSS_CHECK_MIN_RATE` 한 줄로 조정(0.7/0.8 등).

### 일일마감 표준 양식 (★중요)

지점마다 마감 양식이 다르면 합계가 어긋납니다. 아래 표준 양식으로 통일하면 그대로 정확히
분석됩니다. 템플릿 파일: **`templates/일일마감_표준양식.xlsx` / `.csv`** (복사해서 사용).

- **헤더는 한 줄**, 셀 병합 금지. **1행 = 1환자/1거래**.
- 컬럼명은 아래 이름을 **정확히** 사용(띄어쓰기·줄바꿈 없이). 특히 `나만의닥터`는 붙여쓰기.

| 컬럼 | 필수 | 설명 |
|---|---|---|
| `내원순서` | 권장 | 방문 순서(숫자). 없으면 자동 번호 |
| `차트번호` | **필수** | 차트마감·한솔과 매칭하는 핵심 키 |
| `성명` | **필수** | 환자명 |
| `구분` | 권장 | `환불`/`취소` 표기 시 자동 분리·차감(금액은 양수로) |
| `카드` `현금` `이체` | 필수* | 결제수단별 금액(숫자만, 빈칸=0) |
| `여신티켓` `강남언니` `나만의닥터` `제로페이` `기타지역화폐` | 필수* | 플랫폼 결제 금액 |
| `알리페이` `위챗페이` `카카오페이` | 필수* | QR·모바일 간편결제(플랫폼합에 포함) |
| `간편결제(큐릭)` `바비톡` `닥터나우` | 필수* | 큐릭 QR 간편결제·플랫폼앱(플랫폼합에 포함) |
| `비고` 등 | 선택 | 추가 컬럼은 분석에서 무시(결제수단명과 겹치지 않게) |

\* 사용하는 결제수단만 채우면 됨. 대체 컬럼명 허용: `여신티켓`=`여신`, `기타지역화폐`=`기타-지역화폐`,
`위챗페이`=`위쳇페이`, `간편결제`=`간편결제(큐릭)`=`큐릭`, `나만의닥터`=`기타-나만의닥터`.
알리페이·위챗페이·카카오페이·`간편결제(큐릭)`·바비톡·닥터나우는 카드 단말(한솔)을 거치지 않는
QR·모바일·플랫폼 결제이므로 **카드가 아닌 플랫폼**으로 집계됩니다(제로페이와 동일 범주 →
`플랫폼합`·`총액`에 합산). 차트마감(베가스)이 큐릭 결제를 `간편결제(현금영수증)`으로 적어도
'현금영수증' 글자에 속지 않고 **플랫폼**으로 분류합니다(일일마감 `간편결제(큐릭)` 컬럼과 대칭).

- **시트 탭 이름 = 날짜**. `YY.MM.DD`(0패딩, 예: `26.06.02`)를 권장하나, 지점별 실측 형식
  (`06.02` / `6.2` / `26.6.2` / `2026.06.02` / `26년 06월 02일`(압구정) 등)도 자동 매칭합니다
  (`_candidate_tab_names`). 다른 형식이 필요하면 그 함수에 후보를 추가하면 됩니다.
- `총액`/`플랫폼합`은 앱이 결제수단 합으로 자동 계산하므로 넣지 않아도 됩니다.

> **등록 지점(인천·잠실·엔디어트·강남·일산·압구정) 안내**: 일부 시트는 차트번호가 `구분` 바로
> 오른쪽 열에 입력돼 있으나 **그 열 머리글 칸이 비어 있습니다**. 앱이 자동복구하므로 정확히
> 분석·교차검증되지만, 명확성·감사를 위해 해당 머리글 칸에 **`차트번호`를 직접 입력**해 두기를
> 권장합니다(자동복구는 안전망으로 그대로 유지).
>
> 결제수단 열 머리글(카드/현금/이체 등)은 시트에 입력돼 있으면 그대로 보존·인식됩니다(앱이
> `export` 경로로 셀 원본을 읽기 때문). 단 일산·압구정처럼 **열 순서가 지점마다 달라도**(예:
> `이체·현금·카드…`) 머리글대로 정확히 분류합니다.

## 테스트

파서·매칭·합계대사·산출물의 정확도를 회귀 검증하는 pytest 스위트가 `tests/`에 있습니다.

```bash
pip install -r requirements-dev.txt
pytest
```

- `tests/conftest.py` — streamlit 경량 스텁 주입(설치 없이도 순수 로직 테스트 가능).
- `tests/factories.py` — 합성 원본 데이터(한솔/일마/차트) 빌더.
- `test_utils` / `test_parsers` / `test_matching` / `test_reconciliation` / `test_outputs`
  — 시간 파싱·결제수단 분류·승인번호 매칭·환불 net 처리·★★ 확정매칭·엑셀 산출 등을 검증.

> UI 로직은 `app.py`의 `main()` 안에 있어 `import app` 시 실행되지 않습니다(import-safe).
> `streamlit run app.py`는 `__name__ == "__main__"`에서 `main()`을 호출합니다.
