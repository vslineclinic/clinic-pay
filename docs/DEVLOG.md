# 개발일지 (DEVLOG)

**여러 계정이 번갈아 개발하는 저장소다.** 각 작업 세션이 무엇을 왜 바꿨는지 시간순으로
남겨, 다음 세션·다른 계정이 맥락을 잃지 않게 한다.

- **DEVLOG**(이 파일) = 시간순 기록 — *무엇을 왜 했나*. 항목은 지우지 않고 계속 쌓는다.
- **`HANDOVER.md`** = 현재 상태 스냅샷 — *지금 어떻게 생겼나*. 구조가 바뀌면 갱신한다.
- **`CLAUDE.md`** = 작업 규칙 — 어느 계정이든 이 저장소를 열면 따라야 할 규약.

## 기록 방법

코드를 바꿨으면 **아래 템플릿을 복사해 `## 최근 작업` 바로 밑에 추가**하고, 코드와 **같은
커밋**에 포함시킨다(별도 커밋으로 미루면 누락된다).

```markdown
### YYYY-MM-DD · <한 줄 제목> (PR #NN)

- **왜**: 어떤 문제/요구가 있었나 (실사례가 있으면 함께 — "잠실 7/15 조인태 사례")
- **무엇**: 실제로 바꾼 것 (함수·섹션 단위로)
- **결정**: 선택지가 있었다면 무엇을 왜 골랐나 / 무엇을 일부러 안 했나
- **영향**: 건드린 파일 · 테스트 수 · 주의할 부작용
- **남은 것**: 후속 과제나 확인 필요 사항 (없으면 생략)
```

> **왜**와 **결정**을 반드시 적을 것. "무엇"만 있으면 `git log`와 다를 게 없다.
> 다음 사람이 되돌리면 안 되는 결정을 되돌리는 사고를 막는 것이 이 파일의 목적이다.

### 2026-07-19 · 인계 체계 구축: DEVLOG·CLAUDE.md·PR 템플릿 (PR #100 예정)

- **왜**: TEAM 계정으로 개발을 이관하게 됨. 저장소가 여러 계정에서 번갈아 개발되므로,
  어느 계정에서 작업하든 서로의 개발 히스토리를 이해할 수 있는 구조가 필요했다.
  기존엔 `git log`만 있어 "무엇을 했나"는 알아도 **"왜 그렇게 했나"**가 남지 않았다.
- **무엇**:
  - `CLAUDE.md` 신설 — 저장소를 여는 **모든 계정의 세션이 자동으로 읽는** 작업 규칙.
    작업 전 DEVLOG 확인 / 작업 후 DEVLOG 기록 + HANDOVER 갱신을 필수 규칙으로 명시.
    용어·설계 원칙·자주 밟는 지뢰·테스트 규칙 요약 포함.
  - `docs/DEVLOG.md`(이 파일) 신설 + 기존 99개 PR 히스토리 소급 기록.
  - `.github/pull_request_template.md` 신설 — PR 본문에도 같은 인계 정보가 남게.
  - `.claude/settings.json` + `.claude/hooks/devlog-context.sh` 신설 — **SessionStart 훅**.
    세션이 시작되면 DEVLOG '최근 작업' 섹션을 자동으로 컨텍스트에 주입한다(읽기 전용).
  - `HANDOVER.md` 9장 "인계 운영 방식" 추가 + `README.md` 상단에 개발자 문서 안내.
- **결정**:
  - **차단형** 자동화(git hook으로 DEVLOG 미기록 시 커밋 거부)는 **하지 않았다** — git hook은
    계정·환경마다 `.git/hooks` 설치가 필요해 "어느 계정에서든"이라는 목적에 어긋나고, 급한
    핫픽스를 막는다. 대신 **저장소에 커밋되어 자동으로 읽히는 `CLAUDE.md`**로 규약을 세웠다.
  - 반면 **주입형** 자동화(SessionStart 훅)는 **채택했다** — `.claude/settings.json`은 깃에
    커밋되어 별도 설치 없이 모든 계정에 적용되고, 읽기 전용이라 실패해도 작업을 막지 않는다
    (jq·파일이 없으면 조용히 통과). 규칙을 "지시"만 하는 것보다 히스토리를 **눈앞에 띄우는**
    편이 실제 준수율이 높다.
  - DEVLOG와 HANDOVER를 **합치지 않았다** — 시간순 기록과 현재 상태 스냅샷은 수명이 다르다.
    합치면 문서가 계속 부풀거나 과거 맥락이 지워진다.
  - 소급 기록은 **PR 단위**로 묶었다(커밋 단위는 107개라 과다). 4기 구분은 `HANDOVER.md`
    5장과 동일하게 유지해 두 문서가 어긋나지 않게 했다.
- **영향**: 신규 파일 5개(`CLAUDE.md`, `docs/DEVLOG.md`, PR 템플릿, `.claude/settings.json`,
  훅 스크립트) + `HANDOVER.md`·`README.md` 갱신. `app.py` 변경 없음 → 테스트 141개 영향 없음.
  훅은 stdin 페이로드로 파이프 테스트 + `jq -e` 스키마 검증 완료.
- **남은 것**: SessionStart 훅은 세션 시작 시점에만 발화하므로 이번 세션에서는 실제 발화를
  확인할 수 없다. 다음 세션에서 DEVLOG 내역이 자동으로 보이는지 확인할 것
  (안 보이면 `/hooks`를 한 번 열어 설정을 리로드).
